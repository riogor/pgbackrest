# S3 authentication and multipart writes

[Wiki home](../README.md)

Scope: S3-compatible repository operations. [Storage overview](../architecture/storage.md).

`storage/s3/storage.c` implements service request construction/signing, credential retrieval, listings, and shared response handling. Read/write modules expose the common storage interfaces. Endpoint/addressing settings are backend concerns; commands remain storage-agnostic.

AWS Signature Version 4 signing constructs canonical request/header information and an authorization header. Credential paths include supplied keys and supported temporary-role/web-identity retrieval. Expiration is tracked; a saved temporary token is not a permanent credential.

## Multipart writer

`storageWriteS3PartAsync()` first completes an outstanding part request. On the first multipart part it initiates an upload and saves the returned upload ID. It submits numbered parts and records their response information for completion. Buffer size/part size and outstanding request lifetime constrain resource use.

Small-object and multipart finalization paths need separate attention. A part successfully uploaded does not mean a multipart object was completed. When debugging, inspect initiation, individual parts, and completion separately.

Service-side encryption headers and repository client-side encryption are different layers. The latter is applied by command filters before S3 receives stored bytes.

Listings/version handling live in the shared backend, not in backup traversal. Test changed endpoint/signing/multipart behavior in `storage/s3Test.c`; generic POSIX tests cannot establish compatibility with a service's API behavior.

See [HTTP](../network/http.md), [encryption](../formats/encryption.md), and [GCS](gcs.md)/[Azure](azure.md) for different upload protocols.
